Several kinds of Go code in Prysm are generated rather than written by hand. Bazel regenerates the protobuf and SSZ code on every build, but the repository also commits a copy of each generated file so that editors and Go tooling can see it. When you change a source of generated code, refresh those copies and commit them with your change; CI fails the pull request otherwise.

## Before you begin

- [Set up your environment](/developers/environment/).
- `goimports` on your `PATH`: `go install golang.org/x/tools/cmd/goimports@latest`.
- On macOS, GNU `find`, which the scripts in `hack/` require: `brew install findutils`.

## What's generated

| Generated files | Source | Generator | When to regenerate |
| --- | --- | --- | --- |
| `*.pb.go` under `proto/` | `*.proto` files | `protoc` (v25.3, from `protoc_toolchains` in `WORKSPACE`) with `protoc-gen-go`, gRPC and Prysm's `protoc-gen-go-cast` plugins | You changed a `.proto` file. |
| `*.ssz.go` under `proto/` | Per-package YAML configs (for example `proto/prysm/v1alpha1/altair.yaml`) listing the types | [methodical-ssz](https://github.com/OffchainLabs/methodical-ssz), through the `ssz_methodical` rule in `tools/methodical.bzl` | You changed an SSZ type, or added one to a config. |
| `*.minimal.pb.go`, `*.minimal.ssz.go` | The same, with minimal-preset sizes | The same generators | Same as their mainnet twins. |
| Mocks in `testing/mock/`, `testing/validator-mock/`, `validator/client/beacon-api/mock/`, `crypto/bls/common/mock/` | Go interfaces | [`go.uber.org/mock`](https://github.com/uber-go/mock) (`mockgen`) | You changed a mocked interface. |
| `log.go` in each package that logs | The package path | `build/gen/logs.go` | You added a package that logs, or moved one. |
| Spec test package (`testing/spectest/methodical`) | Consensus spec test vectors | `ssz_gen_spectest` rule | You changed the spec version. See [Spec tests](/developers/spec-tests/#update-to-a-new-spec-version). |
| `BUILD.bazel` files and `deps.bzl` | Go imports and `go.mod` | Gazelle | You added files, imports or dependencies. See [Unit tests](/developers/unit-tests/#keep-build-files-in-sync-with-gazelle). |

## Protobuf

Protobuf definitions live in `proto/`: `proto/prysm/v1alpha1/` for Prysm's own consensus types and gRPC services, `proto/engine/v1/` for Engine API types, `proto/eth/` for extensions and a few standard types.

Many fields carry SSZ annotations that depend on the preset, written as placeholders:

```protobuf title="proto/prysm/v1alpha1/beacon_state.proto"
repeated bytes block_roots = 2002
    [ (ethereum.eth.ext.ssz_size) = "block_roots.size" ];
```

Before `protoc` runs, the `ssz_proto_files` rule in `proto/ssz_proto_library.bzl` substitutes the value for the current preset: `8192,32` for mainnet, `64,32` for minimal. The `--//proto:network` setting (set by `--config=minimal`, or by a test's `eth_network`) picks the preset. That's why some packages commit a mainnet `.pb.go` and a `.minimal.pb.go` twin with a `//go:build minimal` constraint.

## SSZ

Prysm's SSZ marshalling, unmarshalling and hash tree root code is generated by methodical-ssz. Each package with SSZ types has one YAML config per group of types, and a matching `ssz_methodical` target in its `BUILD.bazel`:

```text title="proto/prysm/v1alpha1/BUILD.bazel"
ssz_methodical(
    name = "methodical_altair",
    deps = [":go_proto"],
    config_file = "altair.yaml",
    override_package_name = "eth",
    out = "altair.ssz.go",
)
```

The generated files are listed in the package's `go_library` `srcs` as targets (`":methodical_altair"`), so Bazel builds and tests always use freshly generated code. To make a new protobuf message SSZ-serializable, add its name to the right YAML config.

## Refresh the committed protobuf and SSZ files

`hack/check-bazel-drift.sh` regenerates the committed files from Bazel's output.

<Steps>

1. Run the script from the repository root:

   ```bash
   ./hack/check-bazel-drift.sh
   ```

   It builds every non-test target under `//proto/...` and every `ssz_methodical` target, copies each generated `.pb.go` and `.ssz.go` from `bazel-bin` over the committed file, and runs `goimports` and `gofmt` on the copies.

2. Read the result. The script then compares the tree with the last commit:

   - `No unexpected generated-code drift.` The committed files already matched.
   - `Unexpected generated-code drift` followed by a diff. The files changed. If you changed a `.proto` file or an SSZ type, that's expected: the diff is your regenerated code. If you didn't, something in your environment differs; look at the diff before you commit anything.

3. Review and commit the changed files:

   ```bash
   git diff --stat -- proto
   ```

</Steps>

<Aside type="note" title="Minimal-preset twins">
The script regenerates the files of the default (mainnet) preset. The committed `*.minimal.pb.go` and `*.minimal.ssz.go` twins are produced by the repository's `build/gen` generator, which CI runs as described below. If your change affects preset-dependent types, check that CI's generated-code job passes, and regenerate the twins as its error message says if it doesn't.
</Aside>

## Mocks

Mocks are generated with `mockgen`, which the repository declares as a Go tool in `go.mod`. The list of mocks, with the interfaces each one covers, is in `build/gen/mocks.go`. For example, `testing/validator-mock/validator_client_mock.go` mocks the `ValidatorClient` interface from `validator/client/iface`.

After changing an interface, regenerate its mock with the arguments listed for it in `build/gen/mocks.go`, then format the result the way the generator does. Reflection-based mocks (the gRPC and `iface` interfaces) take an import path and interface names:

```bash
go tool mockgen \
  -package=validator_mock \
  -destination=testing/validator-mock/validator_client_mock.go \
  github.com/OffchainLabs/prysm/v7/validator/client/iface ValidatorClient
goimports -w testing/validator-mock/validator_client_mock.go
gofmt -s -w testing/validator-mock/validator_client_mock.go
```

Source-based mocks (under `validator/client/beacon-api/mock/` and `crypto/bls/common/mock/`) take the source file instead:

```bash
go tool mockgen \
  -package=mock \
  -source=validator/client/beacon-api/duties.go \
  -destination=validator/client/beacon-api/mock/duties_mock.go
```

## Per-package loggers

Every package that uses logrus has a generated `log.go` declaring its package logger, with the package path as a field:

```go title="beacon-chain/sync/log.go"
// Code generated by "make gen logs"; DO NOT EDIT.
package sync

import "github.com/sirupsen/logrus"

var log = logrus.WithField("package", "beacon-chain/sync")
```

That package path is what <Flag name="log.vmodule" /> matches (see [Debugging and profiling](/developers/debugging/#per-package-log-levels)). When you add a package that logs, it needs its own `log.go`. Copy the pattern with the new package's path, or let the repository's generator write it, as the header says.

## CI checks

| Workflow | What it checks | How to fix |
| --- | --- | --- |
| `check-generated-go.yml` (on changes under `proto/`, `build/gen/`, `go.mod`) | Regenerates everything with the repository's `build/gen` generator (`make gen`) and fails if any file changed, then runs `hack/check-bazel-drift.sh` and fails on any difference between the Bazel output and the committed files. | Regenerate as described above and commit. |
| `check-logs.yml` | Regenerates every `log.go` (`make gen logs`) and fails if one changed or is missing. | Add or fix the package's `log.go`. |
| Gazelle check (`hack/check_gazelle.sh`) | `deps.bzl` matches `go.mod`, and `BUILD.bazel` files match the Go sources. | Run Gazelle. See [Unit tests](/developers/unit-tests/#keep-build-files-in-sync-with-gazelle). |
| `go.yml` | `go mod tidy -diff`, `golangci-lint`, gosec, and a plain `go build ./...`, which can fail if a committed generated file is stale. | Refresh the generated files. |

## Check that it works

Run the drift check on a clean tree:

```bash
./hack/check-bazel-drift.sh
```

It ends with `No unexpected generated-code drift.`

## Troubleshooting

**`Make sure that GNU 'findutils' package is installed`.** You're on macOS without GNU `find`. Install it with `brew install findutils`.

**`goimports: command not found`.** Install it with `go install golang.org/x/tools/cmd/goimports@latest` and make sure `$(go env GOPATH)/bin` is on your `PATH`.

**Bazel builds pass but `go build ./...` or your editor reports missing methods such as `MarshalSSZ`.** The committed `.ssz.go` files are stale. Bazel generated fresh ones during the build, but the checked-in copies are older. Refresh them with `./hack/check-bazel-drift.sh`.

**The drift diff only changes the `protoc` version line in `.pb.go` headers.** The script ignores `protoc (unknown)` versus `protoc v3.21.7` header differences. Any other difference is real.
