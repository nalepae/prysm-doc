Moving validators is safe if you follow one rule: **the same key must never run in two validator clients, not even for a second.** Prepare the new machine first, so your validators are offline only for the wait you choose (at least two epochs, about 13 minutes). A few missed attestations cost very little; a slashing costs far more.

<Aside type="danger" title="Accept the downtime">
Never start the new validator "just before" stopping the old one, and never run a failover copy. Most slashings happen exactly this way. See [Avoid slashing](/validators/avoid-slashing/).
</Aside>

## Before you begin

- The new machine meets the [system requirements](/get-started/system-requirements/) and has Prysm and an execution client installed.
- Access to the keys on the old machine, or the original keystores and their password.
- Your validator indices or public keys, so you can check them on a block explorer.

## Move your validators

<Steps>

1. **Sync the new node while the old one keeps validating.** Start the execution client and beacon node on the new machine with [checkpoint sync](/setup/checkpoint-sync/), **without** a validator client and without keys. Wait until [Is my node healthy?](/operate/check-health/) shows it synced.

2. **Stop and disable the old validator**, so nothing restarts it:

   ```bash
   # systemd
   sudo systemctl disable --now validator

   # Docker Compose
   docker compose stop validator
   docker compose rm -f validator
   ```

   Adjust the name to your setup. The old beacon node can keep running; it holds no keys.

3. **Check that the old validator is really off.** See [the checks below](#make-sure-the-old-validator-is-off). Don't continue until all pass.

4. **Export slashing protection** from the old machine, now that it has stopped signing:

   ```bash
   ./prysm.sh validator slashing-protection-history export \
     --datadir=<OLD_VALIDATOR_DATADIR> \
     --slashing-protection-export-dir=<EXPORT_DIR>
   ```

   This writes `<EXPORT_DIR>/slashing_protection.json`.

5. **Export the keys, then delete them from the old wallet.** Use the original keystores, or export them:

   ```bash
   ./prysm.sh validator accounts backup \
     --wallet-dir=<OLD_WALLET_DIR> \
     --backup-dir=<EXPORT_DIR>

   ./prysm.sh validator accounts delete \
     --wallet-dir=<OLD_WALLET_DIR>
   ```

   Select the keys you are moving. Afterwards, `validator accounts list --wallet-dir=<OLD_WALLET_DIR>` must not show them.

6. **Copy the files to the new machine** over an encrypted channel (`scp`, an encrypted USB drive). Delete any intermediate copies.

7. **Wait at least two epochs** (about 13 minutes) after the old validator stopped. Then look up your validators on a block explorer: the latest epochs must show **missed** attestations. If they show attestations after you stopped the old validator, something is still signing. Stop and find it.

8. **Import slashing protection, then the keys**, on the new machine with its validator stopped:

   ```bash
   ./prysm.sh validator slashing-protection-history import \
     --datadir=<NEW_VALIDATOR_DATADIR> \
     --slashing-protection-json-file=<PATH_TO>/slashing_protection.json

   ./prysm.sh validator accounts import \
     --wallet-dir=<NEW_WALLET_DIR> \
     --keys-dir=<PATH_TO_KEYSTORES>
   ```

   Use the same `--datadir` the validator will run with, or it starts with empty slashing protection.

9. **Start the new validator** with your fee recipient and MEV-Boost settings, and add <Flag name="enable-doppelganger" bin="validator" /> for the first start. It waits a few epochs and refuses to sign if it sees your keys active elsewhere. It's a last line of defense, not a replacement for step 7.

</Steps>

## Make sure the old validator is off

On the old machine:

- **No process runs:** `pgrep -af 'validator|prysm'` prints nothing. On Windows, check Task Manager.
- **Nothing will restart it:** `systemctl is-enabled validator` prints `disabled`; `docker ps -a` shows no validator container with a restart policy; no cron job or script starts it.
- **No keys are left:** `accounts list` doesn't show the moved keys, and the original keystore files are gone.
- **If in doubt, unplug it.** A machine you can't reach is a machine you can't prove is off.
- **VM snapshots:** delete snapshots and images that contain the keys. Restoring one later would bring the validator back.

## Check that it works

- The new validator logs `Validator activated` for each key, then `Submitted new attestations`. With doppelganger protection, the first few epochs have no attestations; that's expected.
- A block explorer shows attestations again a few epochs after you started.

## If the old machine is gone

If it died and you can't export slashing protection: make sure it can never come back online with the keys (wipe or destroy the disk), wait until a block explorer shows several epochs of missed attestations, then import the keys on the new machine without slashing protection.
