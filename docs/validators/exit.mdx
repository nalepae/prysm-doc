Exiting takes a validator out of the network permanently. Once the exit is processed, it stops earning rewards and its whole balance is sent to its withdrawal address.

:::danger[An exit can't be undone]
Once submitted, an exit can't be cancelled, and an exited validator can never validate again. Double-check the public keys you select.
:::

## Before you begin

- Check that the validator has a withdrawal address (credentials starting with `0x01` or `0x02`). With `0x00` credentials, the balance stays locked until you add one. See [Withdrawals and consolidation](/validators/withdrawals/).
- The validator must have been active for at least 256 epochs (about 27 hours).
- A **synced Prysm beacon node** (gRPC on `127.0.0.1:4000` by default) and the validator's wallet.

## Submit a voluntary exit

<Steps>

1. **Keep the validator client running.** It must keep attesting until the exit takes effect, or it loses balance.

2. **Run the exit command:**

   <Tabs syncKey="runner">
   <TabItem label="prysm.sh">

   ```bash
   cd ~/ethereum/consensus
   ./prysm.sh prysmctl validator exit \
     --wallet-dir=./wallet \
     --wallet-password-file=./wallet-password.txt \
     --beacon-rpc-provider=127.0.0.1:4000 \
     --public-keys=<VALIDATOR_PUBKEY> \
     --accept-terms-of-use
   ```

   </TabItem>
   <TabItem label="Binaries">

   ```bash
   prysmctl validator exit \
     --wallet-dir=<WALLET_DIR> \
     --wallet-password-file=<WALLET_PASSWORD_FILE> \
     --beacon-rpc-provider=127.0.0.1:4000 \
     --public-keys=<VALIDATOR_PUBKEY> \
     --accept-terms-of-use
   ```

   </TabItem>
   <TabItem label="Docker">

   ```bash
   docker run -it --rm --network host \
     -v <WALLET_DIR>:/wallet \
     -v <WALLET_PASSWORD_FILE>:/wallet-password.txt:ro \
     gcr.io/offchainlabs/prysm/cmd/prysmctl:<PRYSM_VERSION> \
     validator exit \
     --wallet-dir=/wallet \
     --wallet-password-file=/wallet-password.txt \
     --beacon-rpc-provider=127.0.0.1:4000 \
     --public-keys=<VALIDATOR_PUBKEY> \
     --accept-terms-of-use
   ```

   Replace `<PRYSM_VERSION>` with the release you run, for example <PrysmVersion />.

   </TabItem>
   </Tabs>

   <Flag name="public-keys" bin="prysmctl" /> takes a comma-separated list. Leave it out to pick keys from a menu. <Flag name="exit-all" bin="prysmctl" /> exits every key in the wallet.

3. **Confirm.** Prysm lists the keys and asks:

   ```text
   ===============CONFIRMATION NEEDED===============
   continue with the voluntary exit? (y/n)
   ```

   Type `y`.

4. **Read the result:**

   ```text
   INFO accounts: Voluntary exit was successful for the accounts listed. URLs where you can track each validator's exit:
   https://hoodi.beaconcha.in/validator/<VALIDATOR_PUBKEY>
   ```

   A key that can't exit yet logs `Could not perform voluntary exit for account ...` with the reason.

</Steps>

To sign an exit now and submit it later, add <Flag name="exit-json-output-dir" bin="prysmctl" />: prysmctl writes the signed exit to a file instead of submitting it. A signed exit never expires, so anyone who has the file can exit your validator; store it like a key.

## Exit from your withdrawal address

If you don't have the signing key (for example with a staking service), the withdrawal address of a `0x01` or `0x02` validator can trigger the exit instead. Open **Validator actions** on the Staking Launchpad (`https://launchpad.ethereum.org/en/validator-actions`, or the Hoodi launchpad), connect the wallet that controls the withdrawal address, select the validator and choose **Exit validator**. It costs a small fee.
{/* Verified against EIP-7002 and ethereum/staking-launchpad (dev branch, src/pages/Actions), 2026-09 */}

## What happens next

1. **Exit queue.** The validator waits for its exit epoch: a few epochs when the queue is short, longer when many validators are exiting. Keep the validator client running.
2. **Exited.** After the exit epoch, the validator has no more duties. About 27 hours later (256 epochs) it becomes withdrawable, and you can stop the validator client for these keys.
3. **Withdrawn.** The next automatic withdrawal sweep sends the full balance to the withdrawal address.

## Check that it works

```bash
curl -s http://127.0.0.1:3500/eth/v1/beacon/states/head/validators/<VALIDATOR_PUBKEY_OR_INDEX> \
  | jq '.data.status'
```

Right after submitting, the status may stay `active_ongoing` until a block includes your exit. It then moves through `active_exiting`, `exited_unslashed`, `withdrawal_possible` and finally `withdrawal_done`.

## Troubleshooting

**`could not perform exit: beacon node is syncing.`** Wait until the beacon node is synced.

**Connection refused on port 4000.** `prysmctl validator exit` needs a **Prysm** beacon node. With another client's beacon node, use <Flag name="exit-json-output-dir" bin="prysmctl" /> and submit the file to `/eth/v1/beacon/pool/voluntary_exits` on its REST API.

**The exit was accepted but the status hasn't changed.** It waits until a block includes it, usually within a few slots. If nothing changes after an hour, submit it again.
