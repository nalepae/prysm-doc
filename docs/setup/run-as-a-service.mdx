Running from a terminal is fine for a first test, but a real node must start at boot and restart by itself after a crash. Pick systemd (Linux) or Docker Compose (any OS with Docker). Both use the same layout:

```text
/usr/local/bin/          # beacon-chain, validator, prysmctl, your execution client (systemd only)
/var/lib/ethereum/
├── jwt.hex              # shared by the execution client and beacon node
├── execution/           # execution client data
├── beacon/              # beacon node data
└── validator/           # wallet, wallet-password.txt, slashing protection
```

## Before you begin

- A working setup you've tried in a terminal: see the [Quickstart](/get-started/quickstart/) and [Connect your execution client](/setup/connect-execution-client/).
- For systemd: Prysm's `beacon-chain` and `validator` binaries and your execution client in `/usr/local/bin` (see [Install Prysm](/install/)). Services call the binaries directly, not `prysm.sh`, so nothing updates itself on restart.
- For Docker Compose: Docker Engine with the Compose plugin (`docker compose version` prints v2 or later).
- For the validator: your keystores, from [Create validator keys](/validators/create-keys/), and an address you control for fees.

## Set up the services

The examples use Geth on Hoodi. For another client, see the notes under [Other execution clients](#other-execution-clients).

<Tabs>
<TabItem label="systemd">

<Steps>

1. **Create one unprivileged user per process, the data directories and the JWT secret.** Only the execution client and beacon node can read the secret, through a shared `ethereum` group:

	```bash
	for u in execution beacon validator; do
	  sudo useradd --system --no-create-home --shell /usr/sbin/nologin $u
	done
	sudo install -d -m 0755 /var/lib/ethereum
	sudo install -d -m 0700 -o execution -g execution /var/lib/ethereum/execution
	sudo install -d -m 0700 -o beacon -g beacon /var/lib/ethereum/beacon
	sudo install -d -m 0700 -o validator -g validator /var/lib/ethereum/validator
	sudo groupadd --system ethereum
	sudo usermod -aG ethereum execution
	sudo usermod -aG ethereum beacon
	openssl rand -hex 32 | tr -d "\n" | sudo tee /var/lib/ethereum/jwt.hex > /dev/null
	sudo chown root:ethereum /var/lib/ethereum/jwt.hex
	sudo chmod 0640 /var/lib/ethereum/jwt.hex
	```

2. **Create the execution client service:**

	{/* Verified against Geth v1.17.6 (flags from cmd/utils/flags.go at the v1.17.6 tag), 2026-09 */}

	```ini title="/etc/systemd/system/execution.service"
	[Unit]
	Description=Ethereum execution client
	Wants=network-online.target
	After=network-online.target

	[Service]
	User=execution
	Group=execution
	ExecStart=/usr/local/bin/geth \
	  --hoodi \
	  --datadir=/var/lib/ethereum/execution \
	  --authrpc.jwtsecret=/var/lib/ethereum/jwt.hex
	Restart=on-failure
	RestartSec=5
	TimeoutStopSec=600
	NoNewPrivileges=true
	ProtectSystem=strict
	ReadWritePaths=/var/lib/ethereum/execution
	ProtectHome=true
	PrivateTmp=true

	[Install]
	WantedBy=multi-user.target
	```

3. **Create the beacon node service.** Replace `<YOUR_WALLET_ADDRESS>` with an address you control:

	```ini title="/etc/systemd/system/beacon.service"
	[Unit]
	Description=Prysm beacon node
	Wants=network-online.target execution.service
	After=network-online.target execution.service

	[Service]
	User=beacon
	Group=beacon
	ExecStart=/usr/local/bin/beacon-chain \
	  --hoodi \
	  --datadir=/var/lib/ethereum/beacon \
	  --execution-endpoint=http://127.0.0.1:8551 \
	  --jwt-secret=/var/lib/ethereum/jwt.hex \
	  --checkpoint-sync-url=https://hoodi.beaconstate.ethstaker.cc \
	  --suggested-fee-recipient=<YOUR_WALLET_ADDRESS> \
	  --postpone-shutdown-for-proposals \
	  --disable-log-colors \
	  --accept-terms-of-use
	Restart=on-failure
	RestartSec=5
	TimeoutStopSec=900
	NoNewPrivileges=true
	ProtectSystem=strict
	ReadWritePaths=/var/lib/ethereum/beacon
	ProtectHome=true
	PrivateTmp=true

	[Install]
	WantedBy=multi-user.target
	```

	<Flag name="postpone-shutdown-for-proposals" /> makes a stop or restart wait until no connected validator has a block to propose soon, which can take about 13 minutes; that's why `TimeoutStopSec=900`. <Flag name="accept-terms-of-use" /> is needed because a service can't answer the first-run prompt.

4. **Create the validator's password file and import your keys** as the `validator` user. Replace `<PATH_TO_VALIDATOR_KEYS>` with your keystore folder:

	```bash
	read -rs -p "Wallet password: " PW && printf '%s' "$PW" | sudo tee /var/lib/ethereum/validator/wallet-password.txt > /dev/null && unset PW
	sudo chown validator:validator /var/lib/ethereum/validator/wallet-password.txt
	sudo chmod 0600 /var/lib/ethereum/validator/wallet-password.txt
	sudo cp -r <PATH_TO_VALIDATOR_KEYS> /var/lib/ethereum/validator/import
	sudo chown -R validator:validator /var/lib/ethereum/validator/import
	sudo -u validator /usr/local/bin/validator accounts import \
	  --hoodi \
	  --keys-dir=/var/lib/ethereum/validator/import \
	  --wallet-dir=/var/lib/ethereum/validator/wallet \
	  --wallet-password-file=/var/lib/ethereum/validator/wallet-password.txt \
	  --accept-terms-of-use
	sudo rm -r /var/lib/ethereum/validator/import
	```

	See [Import keys](/validators/import-keys/) for details.

5. **Create the validator service:**

	```ini title="/etc/systemd/system/validator.service"
	[Unit]
	Description=Prysm validator client
	Wants=network-online.target beacon.service
	After=network-online.target beacon.service

	[Service]
	User=validator
	Group=validator
	ExecStart=/usr/local/bin/validator \
	  --hoodi \
	  --datadir=/var/lib/ethereum/validator \
	  --wallet-dir=/var/lib/ethereum/validator/wallet \
	  --wallet-password-file=/var/lib/ethereum/validator/wallet-password.txt \
	  --beacon-rpc-provider=127.0.0.1:4000 \
	  --suggested-fee-recipient=<YOUR_WALLET_ADDRESS> \
	  --disable-log-colors \
	  --accept-terms-of-use
	Restart=on-failure
	RestartSec=5
	TimeoutStopSec=120
	NoNewPrivileges=true
	ProtectSystem=strict
	ReadWritePaths=/var/lib/ethereum/validator
	ProtectHome=true
	PrivateTmp=true

	[Install]
	WantedBy=multi-user.target
	```

6. **Start the node, then the validator** once the beacon node is synced:

	```bash
	sudo systemctl daemon-reload
	sudo systemctl enable --now execution beacon
	sudo systemctl enable --now validator
	```

	`enable` starts each service at boot. `Restart=on-failure` restarts it after a crash.

</Steps>

On mainnet, replace `--hoodi` with `--mainnet` in all three units and use a mainnet [checkpoint sync](/setup/checkpoint-sync/) URL. After you edit a unit, run `sudo systemctl daemon-reload` before restarting it. If you move a data directory, update `ReadWritePaths=` too, or the service fails with `read-only file system`.

**Logs.** Each service logs to the journal:

```bash
journalctl -fu beacon                          # follow the beacon node
journalctl -u validator --since "1 hour ago"   # the last hour
journalctl -u beacon -p warning -b             # warnings and errors since boot
```

The journal rotates by itself. To cap its size, set `SystemMaxUse=2G` in `/etc/systemd/journald.conf` and run `sudo systemctl restart systemd-journald`.

</TabItem>
<TabItem label="Docker Compose">

<Steps>

1. **Create the directories and the JWT secret.** Prysm's images run as UID and GID `1001`, so their directories belong to that ID. Geth's image runs as root.

	```bash
	sudo install -d -m 0700 /var/lib/ethereum
	sudo install -d /var/lib/ethereum/execution
	sudo install -d -m 0700 -o 1001 -g 1001 /var/lib/ethereum/beacon /var/lib/ethereum/validator
	openssl rand -hex 32 | tr -d "\n" | sudo tee /var/lib/ethereum/jwt.hex > /dev/null
	sudo chmod 0644 /var/lib/ethereum/jwt.hex
	mkdir -p ~/ethereum-compose && cd ~/ethereum-compose
	```

	The secret is readable by every container that mounts it, while `/var/lib/ethereum` itself stays closed to other users on the host.

2. **Save the compose file** as `~/ethereum-compose/docker-compose.yml`:

	{/* Checked against the Compose Specification and images gcr.io/offchainlabs/prysm/*:v7.2.0 and ethereum/client-go:v1.17.6, 2026-09. */}

	```yaml title="docker-compose.yml"
	name: ethereum

	# Rotate each container's log at 100 MB and keep 5 files.
	x-logging: &logging
	  driver: json-file
	  options:
	    max-size: "100m"
	    max-file: "5"

	services:
	  execution:
	    image: ethereum/client-go:v1.17.6
	    restart: unless-stopped
	    stop_grace_period: 10m
	    command:
	      - --${NETWORK}
	      - --datadir=/data
	      - --authrpc.addr=0.0.0.0
	      - --authrpc.vhosts=*
	      - --authrpc.jwtsecret=/jwt.hex
	    volumes:
	      - /var/lib/ethereum/execution:/data
	      - /var/lib/ethereum/jwt.hex:/jwt.hex:ro
	    ports:
	      - "30303:30303/tcp"
	      - "30303:30303/udp"
	    logging: *logging

	  beacon:
	    image: gcr.io/offchainlabs/prysm/beacon-chain:${PRYSM_VERSION}
	    user: "1001:1001"
	    restart: unless-stopped
	    stop_grace_period: 15m
	    depends_on: [execution]
	    command:
	      - --${NETWORK}
	      - --datadir=/data
	      - --execution-endpoint=http://execution:8551
	      - --jwt-secret=/jwt.hex
	      - --checkpoint-sync-url=${CHECKPOINT_SYNC_URL}
	      - --suggested-fee-recipient=${FEE_RECIPIENT}
	      - --http-host=0.0.0.0
	      - --rpc-host=0.0.0.0
	      - --postpone-shutdown-for-proposals
	      - --accept-terms-of-use
	    volumes:
	      - /var/lib/ethereum/beacon:/data
	      - /var/lib/ethereum/jwt.hex:/jwt.hex:ro
	    ports:
	      - "13000:13000/tcp"
	      - "13000:13000/udp"
	      - "12000:12000/udp"
	      - "127.0.0.1:3500:3500"
	    logging: *logging

	  validator:
	    image: gcr.io/offchainlabs/prysm/validator:${PRYSM_VERSION}
	    profiles: ["validator"]
	    user: "1001:1001"
	    restart: unless-stopped
	    stop_grace_period: 2m
	    depends_on: [beacon]
	    command:
	      - --${NETWORK}
	      - --datadir=/data
	      - --wallet-dir=/data/wallet
	      - --wallet-password-file=/data/wallet-password.txt
	      - --beacon-rpc-provider=beacon:4000
	      - --suggested-fee-recipient=${FEE_RECIPIENT}
	      - --accept-terms-of-use
	    volumes:
	      - /var/lib/ethereum/validator:/data
	    logging: *logging
	```

	The Engine API (8551) and gRPC (4000) stay inside the Docker network. Only the peer-to-peer ports are published to the internet; the APIs are published to `127.0.0.1` only. `stop_grace_period: 15m` gives <Flag name="postpone-shutdown-for-proposals" /> time to wait for a proposal; Docker's default of 10 seconds would kill the node mid-write.

3. **Save the settings** as `~/ethereum-compose/.env`, next to the compose file:

	```ini title=".env"
	PRYSM_VERSION=<PRYSM_VERSION>
	NETWORK=hoodi
	CHECKPOINT_SYNC_URL=https://hoodi.beaconstate.ethstaker.cc
	FEE_RECIPIENT=<YOUR_WALLET_ADDRESS>
	# Uncomment once your keys are imported:
	# COMPOSE_PROFILES=validator
	```

	Replace `<PRYSM_VERSION>` with the release to run, currently <PrysmVersion />, and `<YOUR_WALLET_ADDRESS>` with an address you control. To update later, change the version and run `docker compose pull && docker compose up -d`. On mainnet, use `NETWORK=mainnet` and a mainnet [checkpoint sync](/setup/checkpoint-sync/) URL.

4. **Start the execution client and beacon node:**

	```bash
	docker compose up -d
	```

	`restart: unless-stopped` restarts a container after a crash or reboot, unless you stopped it yourself.

5. **Add the validator.** Create the password file, import your keys with a one-off container, then turn on the `validator` profile. Replace `<PATH_TO_VALIDATOR_KEYS>` with your keystore folder (readable by UID 1001):

	```bash
	read -rs -p "Wallet password: " PW && printf '%s' "$PW" | sudo tee /var/lib/ethereum/validator/wallet-password.txt > /dev/null && unset PW
	sudo chown 1001:1001 /var/lib/ethereum/validator/wallet-password.txt
	sudo chmod 0600 /var/lib/ethereum/validator/wallet-password.txt
	docker compose run --rm -v <PATH_TO_VALIDATOR_KEYS>:/keys:ro \
	  validator accounts import \
	  --hoodi \
	  --keys-dir=/keys \
	  --wallet-dir=/data/wallet \
	  --wallet-password-file=/data/wallet-password.txt \
	  --accept-terms-of-use
	```

	Uncomment `COMPOSE_PROFILES=validator` in `.env`, then run `docker compose up -d` again.

</Steps>

**Logs.** `docker compose logs -f beacon` follows the beacon node; `docker compose logs --since 1h validator` shows the last hour. The `x-logging` block rotates the logs; without it, Docker keeps them forever.

**Everyday commands.** `docker compose stop` stops everything, `docker compose up -d` starts it again, and `docker compose restart beacon` restarts one service. `docker compose down` removes the containers; your data stays in `/var/lib/ethereum`.

</TabItem>
</Tabs>

:::danger[One validator client per key]
Never run the validator service on two machines, or next to another validator client, with the same keys. Both would sign, and the keys would be slashed. See [Avoid slashing](/validators/avoid-slashing/).
:::

Prysm also keeps up to 24 hours of debug logs in `<datadir>/logs/` (at most about 500 MB). To turn that off, add <Flag name="disable-ephemeral-log-file" />.

## Other execution clients

Replace the Geth command with your client's, using `/var/lib/ethereum/execution` and `/var/lib/ethereum/jwt.hex` as the paths. The flags are on [Connect your execution client](/setup/connect-execution-client/). For Docker, bind the Engine API to `0.0.0.0` inside the container so the `beacon` container can reach it, and allow the `execution` host name.

{/* Verified against Nethermind 2.0.0, Besu 26.9.0, Erigon v3.7.0, Reth v2.7.0 and Ethrex v27.0.0 (CLI docs and images at those tags), 2026-09. */}

| Client | systemd | Docker image and user |
| --- | --- | --- |
| Nethermind | Ships as a folder: unpack it into `/opt/nethermind` and call `/opt/nethermind/nethermind`. Set `--JsonRpc.EngineHost` and `--JsonRpc.EnginePort` together. | `nethermind/nethermind:2.0.0`, runs as root |
| Besu | Ships as a folder: unpack it into `/opt/besu` and call `/opt/besu/bin/besu`. Needs Java 25. | `hyperledger/besu:26.9.0`; run with `user: "1000:1000"` and `chown 1000:1000` the data directory. Use `--engine-host-allowlist=*` and `--rpc-http-host=0.0.0.0`. |
| Erigon | Add `--externalcl`. Open port 42069 (TCP and UDP) for its history downloads. | `erigontech/erigon:v3.7.0`, runs as UID 1000: `chown 1000:1000` the data directory. |
| Reth | Add `--full` and `--log.file.directory=/var/lib/ethereum/execution/logs`: its default log location is in a home directory, which the unit blocks. | `ghcr.io/paradigmxyz/reth:v2.7.0`, runs as root. The command starts with `node`. |
| Ethrex | Data goes in a subfolder named after the network. | `ghcr.io/lambdaclass/ethrex:27.0.0` (no `v` in the tag), runs as root |

<Tabs>
<TabItem label="systemd">

```bash
systemctl is-active execution beacon validator
curl -s http://127.0.0.1:3500/eth/v1/node/syncing
```

</TabItem>
<TabItem label="Docker Compose">

```bash
docker compose ps
curl -s http://127.0.0.1:3500/eth/v1/node/syncing
```

</TabItem>

All services should be `active` (systemd) or `running` (Compose). Once the node is synced, `is_syncing` is `false`. Reboot the machine once and run the same commands: everything should come back by itself. See [Is my node healthy?](/operate/check-health/) for the full check.

## Troubleshooting

**`status=217/USER` (systemd).**
The `User=` in the unit doesn't exist. Create it as in step 1.

**`permission denied` reading `jwt.hex`.**
With systemd, the service user isn't in the `ethereum` group or the file isn't `root:ethereum 0640`; test with `sudo -u beacon cat /var/lib/ethereum/jwt.hex`. With Docker, check that the file is `0644`.

**`permission denied` or `read-only file system` in the data directory.**
The directory belongs to another user, often after running a binary by hand as root. Fix it with `sudo chown -R beacon:beacon /var/lib/ethereum/beacon` (systemd) or `sudo chown -R 1001:1001 /var/lib/ethereum/beacon` (Docker). With systemd, also check `ReadWritePaths=`.

**The service restarts in a loop.**
Read the last error with `journalctl -u beacon -n 50 --no-pager` or `docker compose logs --tail 50 beacon`. A misspelled or removed flag stops Prysm at startup; compare with the [beacon-chain reference](/reference/cli/beacon-chain/).
