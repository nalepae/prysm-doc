This guide gets a full Ethereum node running on one machine: an **execution client** and a **Prysm beacon node**. Pick your setup below, and every command on the page updates to match it.

:::tip[Start on Hoodi]
Choose **Hoodi testnet** for your first run. It behaves like mainnet, and mistakes cost nothing. Check your machine against the [system requirements](/get-started/system-requirements/) first.
:::

## Check that it works

Leave both programs running and open a new terminal. Ask the beacon node whether it has caught up:

<Tabs syncKey="os">
<TabItem label="Linux, macOS">

```bash
curl -s http://localhost:3500/eth/v1/node/syncing
curl -s http://localhost:3500/eth/v1/node/peer_count
```

</TabItem>
<TabItem label="Windows">

```powershell
curl.exe -s http://localhost:3500/eth/v1/node/syncing
curl.exe -s http://localhost:3500/eth/v1/node/peer_count
```

</TabItem>
</Tabs>

Your node is ready when the first command shows all three of these:

- `"is_syncing":false`: the beacon node has caught up with the chain.
- `"is_optimistic":false`: the execution client has caught up too. It stays `true` while the execution client is still syncing, which can take hours.
- `"el_offline":false`: the beacon node can reach the execution client.

The second command should show a `connected` count that grows over the first minutes. Tens of peers is normal; Prysm aims for up to 70.

In the beacon node's terminal, a synced node logs one line per block, about every 12 seconds:

```text
INFO blockchain: Synced new block block=0x5b7dd003... epoch=385801 finalizedEpoch=385799 finalizedRoot=0xcdeff59f... sinceSlotStartTime=1.9s slot=12345650
```

Every minute it also logs `Connected peers` with the current `total`. If you see few peers, open your P2P ports: see [Ports, peers and router setup](/setup/networking/). For more checks, see [Is my node healthy?](/operate/check-health/).
