Prysm pins its Bazel version in the `.bazelversion` file at the root of the repository (currently `7.4.1`). [Bazelisk](https://github.com/bazelbuild/bazelisk) is a small launcher that reads this file, downloads that exact Bazel release and runs it. Install Bazelisk as `bazel` and you never manage Bazel versions by hand.

## Before you begin

- A clone of the repository. See [Overview](/developers/).
- On macOS, the Xcode Command Line Tools:

  ```bash
  xcode-select --install
  ```

  Bazel uses them for the C code in Prysm's dependencies. On Linux, the repository registers a hermetic C toolchain, so the system compiler isn't used.

You don't need to install Go for Bazel builds. Bazel downloads the Go SDK set in `WORKSPACE` (`go_register_toolchains(go_version = "1.26.5")`), which matches `go.mod`. Install Go separately only if your editor needs it.

## Install Bazelisk

<Steps>

1. Install Bazelisk and make it available as `bazel`.

   <Tabs>
   <TabItem label="Linux">

   Download the binary for your CPU from the Bazelisk releases and put it on your `PATH` as `bazel`. Use `bazelisk-linux-arm64` on ARM64:

   ```bash
   mkdir -p "$HOME/bin"
   curl -L -o "$HOME/bin/bazel" \
     https://github.com/bazelbuild/bazelisk/releases/latest/download/bazelisk-linux-amd64
   chmod +x "$HOME/bin/bazel"
   ```

   Make sure `$HOME/bin` is on your `PATH`.

   If you already have Go, this is how Prysm's CI installs it:

   ```bash
   go install github.com/bazelbuild/bazelisk@latest
   ln -sf "$(go env GOPATH)/bin/bazelisk" "$HOME/bin/bazel"
   ```

   </TabItem>
   <TabItem label="macOS">

   With [Homebrew](https://brew.sh/):

   ```bash
   brew install bazelisk
   ```

   The formula installs both `bazelisk` and `bazel`, and both run Bazelisk.

   </TabItem>
   </Tabs>

   {/* Verified against bazelisk v1.29.0 release assets and the Homebrew bazelisk formula, 2026-09 */}

2. From the root of your clone, check the version. The first run downloads Bazel.

   ```bash
   bazel version
   ```

   You should see the Bazelisk version and the pinned Bazel release:

   ```text
   Bazelisk version: <BAZELISK_VERSION>
   Build label: 7.4.1
   ```

</Steps>

Bazelisk picks the version from the `.bazelversion` of the directory you run it in, so a branch that bumps Bazel switches automatically on your next command. Outside a Bazel workspace it falls back to the latest Bazel release, which is why `bazel version` must run inside the clone.

## Check that it works

List the binary targets. This loads the repository and fetches the first dependencies:

```bash
bazel query 'kind(go_binary, //cmd/...)'
```

You should see:

```text
//cmd/beacon-chain:beacon-chain
//cmd/client-stats:client-stats
//cmd/prysmctl:prysmctl
//cmd/validator:validator
```

## Bazel settings in the repository

The root `.bazelrc` imports fragments from `build/bazelrc/`. A few defaults affect what you see day to day:

| Setting | Effect |
| --- | --- |
| `--keep_going` | Builds and tests everything it can instead of stopping at the first failure. |
| `test --test_output=errors` | Prints the log of failing tests to the terminal. |
| `--sandbox_default_allow_network=false` | Build actions and tests have no network access unless the target is tagged `requires-network`. |
| `--incompatible_strict_action_env` | Actions get a fixed `PATH`, so changes to your shell environment don't invalidate the cache. |

The named configs (`release`, `minimal`, `debug` and others) are covered in Build with Bazel and Unit tests.

### Personal settings and a disk cache

Put your own flags in `~/.bazelrc`, which Bazel reads in addition to the repository's `.bazelrc` and which isn't part of the repository. The most useful one is a disk cache, which keeps build results across `bazel clean` and across several clones:

```bash title="~/.bazelrc"
build --disk_cache=~/.cache/bazel-disk
```

Bazel's own output base lives under `~/.cache/bazel` on Linux and `/private/var/tmp/_bazel_$USER` on macOS. The disk cache isn't pruned automatically; delete it when it gets too big.

## Troubleshooting

**`bazel: command not found` after `go install`.** The binary is called `bazelisk` and lives in `$(go env GOPATH)/bin`. Create the `bazel` symlink shown above and put its directory on your `PATH`.

**`bazel version` shows a Bazel release other than the pinned one.** You ran it outside the clone, or `bazel` on your `PATH` is a real Bazel install rather than Bazelisk. Check with:

```bash
which bazel
```

**`xcrun: error: invalid active developer path` on macOS.** The Xcode Command Line Tools are missing. Install them:

```bash
xcode-select --install
```

Then run this so Bazel detects the toolchain again:

```bash
bazel clean --expunge
```
